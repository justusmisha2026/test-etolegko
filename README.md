# Adrobot — управление кампаниями Keitaro

Приложение на FastAPI и SQLAlchemy по [ТЗ](docs/specs/adrobot-keitaro-audit.md). Создаёт кампанию с географическим потоком на Google и замыкающим потоком на оффер. Редактор добавляет и удаляет привязки существующих офферов, автоматически распределяя доли.

## Запуск

Проверено на Python 3.14.6. Проект требует Python 3.12 или новее; остальные версии отдельно не проверялись. Точные версии установленных зависимостей, включая инструменты проверки, записаны в `requirements.lock`.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
```

В новой копии проекта создайте `.env` из `.env.example`. Не перезаписывайте существующий `.env`: он может содержать ваш ключ. Пример включает демонстрационный режим.

```sh
.venv/bin/alembic upgrade head
.venv/bin/python -m uvicorn adrobot.main:app --host 127.0.0.1 --port 8765
```

Откройте [приложение](http://127.0.0.1:8765/). В демонстрационном режиме кампании, офферы и журнал находятся в памяти и сбрасываются при перезапуске. Запросы к Keitaro не отправляются. Настоящая БД используется при `ADROBOT_DEMO=false`; приложение не создаёт её таблицы автоматически.

Запускайте один процесс Uvicorn, без `--workers`. Интерфейс предназначен для локального использования: в нём нет пользовательской авторизации. Для сетевого размещения потребуются отдельные аутентификация и настройки доступа. Приложение проверяет Host и Origin и требует специальный заголовок для изменяющих запросов.

## Подключение Keitaro

Настройки задаются в `.env` либо переменными окружения; переменные окружения имеют приоритет.

| Переменная | Назначение |
| --- | --- |
| `ADROBOT_DEMO` | `true` — демонстрация, `false` — настоящий API |
| `ADROBOT_DATABASE_URL` | По умолчанию `sqlite:///./adrobot.db` |
| `ADROBOT_KEITARO_URL` | HTTPS origin без `/admin`, например `https://tlgk.host` |
| `ADROBOT_API_KEY` | Существующий ключ Admin API; используется только сервером |
| `ADROBOT_CAMPAIGN_PREFIX` | Ваш префикс в формате `test_фамилия_` |
| `ADROBOT_WRITES_ENABLED` | Разрешение записи; по умолчанию `false` |
| `ADROBOT_EDITOR_ENABLED` | Разрешение редактора, по умолчанию `true` |
| `ADROBOT_TIMEOUT_SECONDS` | Тайм-аут запроса, по умолчанию 15 секунд |

Ключ хранится только в локальном `.env`, исключённом из Git; в новой копии репозитория его нужно задать самостоятельно. Пароль от админки приложению не нужен. Для чтения справочников без записи:

```sh
.venv/bin/python -m adrobot.check_connection
```

Для работы со стендом установите `ADROBOT_DEMO=false`, заполните ключ и свой префикс, выполните миграцию и включите `ADROBOT_WRITES_ENABLED=true`. Перезапустите сервер после изменения конфигурации. Наличие ключа в настройках не считается доказательством соединения: ошибки доступа показываются при загрузке данных.

Публичная [документация Admin API](https://docs.keitaro.io/en/development/admin-api.html) и [OpenAPI](https://admin-api.docs.keitaro.io/openapi.json) использованы как исходный контракт. Проверенные особенности конкретного стенда и оставшиеся границы описаны в [отчёте интеграции](docs/integration-check.md).

## Создание кампании

Выберите название, страну ISO 3166-1 alpha-2, существующий оффер, домен, группу и источник. Префикс добавляется один раз. Перед записью приложение повторно проверяет доступность выбранных записей. Ограничение названия в форме — 150 символов без префикса; это локальное ограничение приложения, не заявленный предел Keitaro.

Последовательность: выключенная кампания → приоритетный поток `forced` с фильтром `country/accept` и HTTP 302 на `https://google.com/` → поток `default` с выбранным оффером → повторное чтение настроек → активация → повторная проверка. Привязка посетителей отключена; ротация кампании — по позиции.

Журнал SQLAlchemy фиксирует UUID операции, исходные параметры, префикс, шаг, статус, ID кампании и обезличенную ошибку. На шаге `complete` проверено состояние сразу после создания; последующие ручные изменения кампании не переписывают историю успешной операции.

Повторный POST с тем же UUID и теми же параметрами возвращает сохранённую операцию. Тот же UUID с другими параметрами возвращает 409. HTTP-клиент не повторяет запросы записи автоматически.

Если связь потеряна, откройте журнал и выберите «Сверить состояние». Сверка ищет кампанию по уникальному alias операции и читает её потоки. Она не создаёт объекты. Отсутствие кампании в ответе после тайм-аута не доказывает, что запрос не выполнился: состояние остаётся неопределённым.

«Продолжить создание» доступно для подтверждённого частичного результата. Приложение проверяет выключенное состояние, принадлежность кампании, существующие потоки и незавершённый шаг, затем продолжает с него. Неопределённый результат (`uncertain`) и операция, оставшаяся `running` после прерывания процесса, не повторяются таким способом. После сверки неустранённая неопределённость требует проверки в админке. Новая операция с новым UUID — отдельное намерение создать кампанию, а не средство обхода неопределённости.

## Редактор и доли

Выберите существующую кампанию, затем явно выберите поток. Запись разрешена только в кампании с настроенным собственным префиксом и поток с `schema=landings`, уже содержащий офферы. Другие кампании доступны для просмотра. Глобальные офферы не создаются и не удаляются.

По уточнению пользователя доли рассчитываются автоматически; дубли и удаление последнего активного оффера запрещены, Stats/Trends не входят в текущий объём. Конкретизация расчёта в реализации:

- Для `n` активных офферов `q, r = divmod(100, n)`. Первые `n-r` получают `q`, последние `r` — `q+1` процентов.
- Один оффер: 100%; два: 50/50; три: 33/33/34; шесть: 16/16/17/17/17/17.
- Новые офферы добавляются в конец. Оставшиеся сохраняют порядок. После изменения состава доли пересчитываются целиком.
- Состояние существующих выключенных привязок сохраняется, их доля при перерасчёте — 0%. Сумма активных долей — 100%.
- В редакторе допускается до 100 привязок. Это локальная граница, позволяющая выдавать каждому активному офферу хотя бы 1%; не лимит API.
- При открытии показываются фактические доли Keitaro. Без изменения состава они не перезаписываются. Ручного ввода процентов нет.

Перед сохранением сервер сравнивает полный снимок кампании и потоков с ревизией формы. При отличии возвращает 409. Записывается только `offers` выбранного потока; после записи проверяются состав, проценты и сохранность соседних полей. Серверные `updated_at` не считаются пользовательскими настройками.

Между повторным чтением и записью остаётся окно конкурентного изменения внешним клиентом: подтверждённого условного PUT у этого API нет. Локальная блокировка сериализует запросы одного процесса, но не защищает от параллельной админки. Обнаруженное после записи отличие показывается как конфликт; автоматический откат чужих изменений не выполняется.

## Проверка

```sh
.venv/bin/python -m pytest -q
.venv/bin/ruff check adrobot tests migrations
.venv/bin/ruff format --check adrobot tests migrations
```

Тесты проверяют распределение для 1–100 офферов, входную валидацию, контракт HTTP-клиента, отсутствие слепых повторов, отказы на каждом шаге создания, продолжение частичного результата, сохранение журнала после перезапуска, конфликт редактирования и сохранность соседних данных. Тесты подменяют Keitaro и не обращаются к стенду. Проверяется также миграция `upgrade → downgrade → upgrade` на отдельной временной БД. `downgrade base` удаляет журнал — не выполняйте его на нужной рабочей БД.

Регрессионные проверки обработчиков редактора запускаются отдельно на Node.js 22 или новее: `node --test tests/frontend.test.cjs`. Они выполняют клиентский код с подменой DOM и сети: проверяют возврат выключенного оффера и восстановление исходных долей после отмены добавления или удаления. Дополнительные npm-зависимости не нужны.

Браузерные E2E запускаются отдельно:

```sh
.venv/bin/python -m pip install -r requirements-e2e.lock
.venv/bin/python -m playwright install chromium
.venv/bin/python -m pytest -q e2e --browser chromium --tracing retain-on-failure --screenshot only-on-failure
```

Каждый E2E-тест запускает собственный Uvicorn на свободном локальном порту, настоящее приложение и отдельное демонстрационное хранилище. Проверяются создание и журнал, сохранение после перезагрузки страницы, запрет удаления последнего оффера, обе регрессии редактора и конфликт двух форм. Локальный `.env` не читается этими экземплярами приложения, ключ не требуется. Настоящие запросы в Keitaro не выполняются. Диагностика падений сохраняется в `test-results/` и исключена из Git.

Workflow [Checks](.github/workflows/checks.yml) запускает Ruff, Python-тесты, Node-тесты и Chromium E2E на push, pull request и вручную. CI использует Python 3.14 и Node.js 22, не получает секреты Keitaro и сохраняет диагностические артефакты при ошибках. Дополнительный объём описан в [ТЗ проверки и CI](docs/specs/verification-ci.md).

Ручной сценарий в демо: создать кампанию для AU с оффером A → выбрать поток Offers → добавить B и C → проверить 33/33/34 → сохранить → удалить B → проверить 50/50 → сохранить → убедиться, что последний активный оффер удалить нельзя. Отдельно открыть два окна редактора: сохранение в первом должно сделать форму второго устаревшей.

На реальном стенде проверяйте только собственные тестовые объекты. Маршрутизация выбранной, другой и неизвестной страны, а также повторного визита проверена штатным симулятором Keitaro; [результаты и ограничения](docs/routing-check.md). Кампания после проверки выключена. Последующее контрольное чтение Admin API вернуло 401: перед новым подключением приложения проверьте актуальность своего ключа.

## Структура и сдача

`main.py` — HTTP и жизненный цикл; `schemas.py` — входные модели; `domain.py` — payload и распределение долей; `services.py` — операции и проверки состояния; `keitaro.py` — HTTP-адаптер; `database.py` — журнал; `demo.py` — подменяемое хранилище; `static/` — интерфейс без сборщика. Миграции находятся в `migrations/`.

Репозиторий для сдачи: [justusmisha2026/test-etolegko](https://github.com/justusmisha2026/test-etolegko). Отправка ссылки рекрутеру выполняется отдельно. Не публикуйте `.env`, `.db`, временные ответы API и данные входа.

ИИ использовался для аудита задания, проектирования, генерации и исправления реализации, тестов и документации. Условия редактора были уточнены у пользователя; расхождения с реальным API выявлены интеграционными проверками. Описание не утверждает соответствие непросмотренной части исходного видео.
