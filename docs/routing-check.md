# Проверка маршрутизации в симуляторе Keitaro

Дата: 20.11.2026. Проверена собственная тестовая кампания на предоставленном стенде.
Пользователь отдельно разрешил временный переход `disabled → active` и последующее выключение. Все запуски выполнены через штатную «Симуляцию трафика» в админке.

## Результаты

| Сценарий | Ввод | Фактическое определение Keitaro | Результат |
| --- | --- | --- | --- |
| Выбранная страна | Тестовый IP выбранной страны, один запрос | `Country: AU`, unique=yes | Фильтры приняли визит; `PositionStrategy` выбрала Google-поток, действие `http`. В конфигурации этого потока URL `https://google.com/` |
| Другая страна | Тестовый IP другой страны, один запрос | `Country: US` | Фильтр страны отклонил визит; `DefaultStrategy` выбрала замыкающий поток, назначенный оффер, действие оффера `local_file` |
| Неизвестная страна | Тестовый IP без географии, один запрос | `Country: null` | Фильтр страны отклонил визит; замыкающий поток, назначенный оффер |
| Повторный визит | Повтор Тестовый IP выбранной страны с тем же User-Agent, один запрос | `Country: AU`, unique in campaign=no, unique in stream=no; сессия найдена | Снова выбран Google-поток с действием `http` |

Источник — журналы четырёх запусков симулятора. [Машиночитаемая выписка](simulation-results.json) сохраняет определённую страну, уникальность и выбор потока/оффера. Все IP-адреса, идентификаторы кампании, потоков, офферов, сессий и SubID исключены из публикуемой выписки. User-Agent был одинаковым во всех запусках: штатное значение симулятора для Mobile Safari/iPhone.

Каждый журнал содержит `Saving clicks: 1`: всего четыре симуляции по одному запросу. После перезагрузки админка показала два клика Google-потока (один уникальный) и два клика офферного потока (два уникальных). Статистика не очищалась.

## Завершение и ограничения

Кампания возвращена в `disabled`, нажата кнопка сохранения. После полной перезагрузки страницы вновь подтверждены имя собственной кампании, отметка «Сохранено» и выбранное состояние «Выключена». [Снимок переключателя](screenshots/campaign-disabled.jpg) обрезан до состояния, чтобы не включать расположенный выше Click API token.

Дополнительное контрольное чтение GET кампании через Admin API существующим локальным Admin API-ключом вернуло HTTP 401. Причина не установлена; ключи и права не менялись. Поэтому финальное состояние подтверждено повторной загрузкой UI, а не этим API-запросом. Перед дальнейшей работой приложения в реальном режиме нужно проверить актуальность ключа. Предыдущие успешные API-проверки относятся к моменту их выполнения.

Проверена маршрутизация серверным симулятором, включая распознанный повторный визит. Это не проверка загрузки Google или страницы оффера в настоящем браузере и не подтверждение всех вариантов cookie/Click API. Полное соответствие недоступной части видеореференса по-прежнему не утверждается.

## Автоматические проверки

Пять Chromium E2E, 144 Python-теста и три проверки обработчиков JavaScript прошли локально. [GitHub Actions последнего коммита с отчётом](https://github.com/justusmisha2026/test-etolegko/actions/runs/44715962564) завершился `success` для `0e5eae1d30d2f70558b9b9fcd2a54a974b96f5cc`. Этот коммит отличается от первого успешного запуска только документацией; новый отчёт маршрутизации не меняет исполняемый код.
