# Проверка интеграции Keitaro

Дата: 20.11.2026. Стенд: `https://tlgk.host`. Проверки выполнялись существующим ключом предоставленной учётной записи. Новые ключи и права не создавались. Версия сервера не установлена; ниже зафиксировано наблюдаемое поведение API, а не предположение о версии.

## Проверенные чтения

HTTP 200 получен для `GET /admin_api/v1/campaigns?limit=1&offset=0`, `/domains`, `/groups?type=campaigns`, `/traffic_sources`, `/offers`, `/streams_actions`, `/stream_filters`, а также чтения кампании и её потоков. Фильтр `country` и действие `http` присутствуют в справочниках. Действие `http` описано стендом как HTTP 302.

Ответы списков — JSON-массивы; идентификаторы — целые числа. `group_id` кампании возвращается целым числом. Фильтр страны возвращает `payload` как массив строк. `offers` потока содержит дополнительные серверные поля, поэтому в запрос передаются только `offer_id`, `share`, `state`.

## Собственная тестовая кампания

По явно указанному пользователем префиксу создана кампания `test_justus_integration_20261120`, ID `216565`. Потоки: `1331219` и `1331220`. Существующие общие справочники не изменялись. Использованы домен `1813`, группа FORTESTS `10332`, источник FORTESTS `836`, оффер `18813`. Эти значения — параметры конкретной проверки, в приложении они не зашиты.

1. `POST /campaigns` принял уникальный непустой alias, `group_id` строкой, выбранные привязки и начальное состояние `disabled`.
2. `POST /streams` создал `forced/redirect/http` с `action_payload=https://google.com/`, фильтром AU и позицией 1; второй поток — `default/landings/http`, позиция 2, выбранный оффер с долей 100.
3. Первый проход проверки выявил нормализацию: запрос `bind_visitors=null` возвращается как пустая строка. Кампания осталась выключенной; приложение показало частичный результат. Нормализация внесена в адаптацию ответа и покрыта отдельным тестом.
4. Через реализованный сценарий продолжения операция завершилась без создания второй кампании или дублирования потоков. Повторное чтение подтвердило активную кампанию и обе конфигурации.
5. Проверена замена массива `offers` на собственной кампании и восстановление исходного массива в `finally`. Пустой массив удаляет привязки; переданный массив восстанавливает их. Это проверка низкоуровневого API; интерфейс приложения запрещает удалять последний активный оффер.
6. При первой сверке после изменения массива полное сравнение не прошло; причина того конкретного расхождения не установлена. Повторная диагностическая запись показала изменение серверного времени привязки. Контрольный проход после явного выключения кампании подтвердил восстановление оффера и равенство остальных полей после исключения `updated_at`. Это не доказывает отсутствие всех возможных побочных эффектов API.
7. Финальное чтение подтвердило: кампания выключена, исходный оффер восстановлен, остальные проверяемые поля кампании и потоков сохранены. Тестовые объекты оставлены выключенными для проверки результата; удаления не выполнялись.

Ключ и пароль не включены в этот отчёт. Локальный `.env` исключён из Git. Тестовая операция записана в локальную БД; она отражает завершённое создание, последующее выключение выполнено в рамках проверки стенда.

## Границы доказательства

На стенде доступен один глобальный оффер. Положительный сценарий с несколькими разными офферами проверен через демонстрационный интерфейс и автоматические тесты; реальные глобальные офферы для проверки не создавались. Замена массива и сохранность соседних полей проверены на реальном API отдельно.

Реальные переходы и симуляция географии/повторных визитов не выполнялись. Симулятор открыт, но повторное включение собственной кампании для этой проверки отклонено автоматической проверкой разрешений: активация может запустить реальную маршрутизацию, и требуется отдельное подтверждение пользователя. Отклонённая команда не выполнялась; альтернативный способ включения не использовался. Проверены настройки маршрутизации, но не фактический выбор потока трекером для каждого вида визита. Полная логика исходного видео не подтверждена; используется уточнённое пользователем условие автоматических долей и явно описанная в README формула округления.

Исходные документы: [Admin API](https://docs.keitaro.io/en/development/admin-api.html), [OpenAPI](https://admin-api.docs.keitaro.io/openapi.json), [первоначальный аудит](specs/adrobot-keitaro-audit.md). Точное поведение установленного API выше установлено запросами к стенду во время реализации.
